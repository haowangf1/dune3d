# 拖拽编辑-约束联动-撤销重做流程

这篇只讲一个常见场景：

- 平时没有显式进入某个工具
- 直接在视图里选中模型或草图对象并拖动
- 几何会根据约束实时变化
- 放开后还能 `undo / redo`

代码层面，这不是“完全没有 tool”，而是：

- `Editor` 先把这次操作识别成一次拖拽
- 超过拖动阈值后，自动启动一个瞬时的 `MOVE` tool
- 这个 `MOVE` tool 在每次鼠标移动时修改文档、触发求解、刷新画布
- 最后 `commit` 成为一条 history，所以可以撤销重做


## 1. 总体主链

可以先记这条线：

```text
左键按下选中对象
  -> Editor 记录拖拽候选
  -> 鼠标移动超过阈值
  -> Editor 自动启动 transient MOVE tool
  -> ToolMove 每帧修改实体参数
  -> set_group_solve_pending(...)
  -> solve_current(...)
  -> Document::update_pending()
       -> generate
       -> solve
       -> update_solid_model
  -> Editor::canvas_update()
  -> Canvas::on_render()
  -> 左键确认 commit
  -> history_push("tool")
  -> 支持 undo / redo
```


## 2. 平时没进工具，为什么拖动时还是会进入编辑流程

入口在：

- `src/editor/editor.cpp`
- `Editor::handle_click(...)`

左键按下时，不会立刻启动 tool，而是先记录“拖拽候选”：

```cpp
else if (button == 1) {
    auto hover_sel = get_canvas().get_hover_selection();
    if (!hover_sel)
        return;

    auto sel = get_canvas().get_selection();
    if (!sel.contains(hover_sel.value()))
        sel = {*hover_sel};

    m_drag_tool = get_tool_for_drag_move(false, sel);
    if (m_drag_tool != ToolID::NONE && m_core.tool_can_begin(m_drag_tool, sel).get_can_begin()) {
        get_canvas().inhibit_drag_selection();
        m_cursor_pos_win_drag_begin = get_canvas().get_cursor_pos_win();
        m_selection_for_drag = sel;
    }
}
```

而默认拖拽工具就是：

```cpp
ToolID Editor::get_tool_for_drag_move(bool ctrl, const std::set<SelectableRef> &sel)
{
    return ToolID::MOVE;
}
```

意思是：

- 平时看起来像“直接拖”
- 但代码已经把它预判成“可能要进入 `MOVE` tool”


## 3. 鼠标移动超过阈值后，会自动启动 `MOVE` tool

真正启动发生在：

- `src/editor/editor.cpp`
- `Editor::handle_cursor_move()`

```cpp
else {
    if (m_drag_tool == ToolID::NONE)
        return;
    if (m_selection_for_drag.size() == 0)
        return;
    if (get_canvas().get_is_long_click())
        return;
    auto pos = get_canvas().get_cursor_pos_win();
    auto delta = pos - m_cursor_pos_win_drag_begin;
    if (glm::length(delta) > 10) {
        ToolArgs args;
        args.selection = m_selection_for_drag;
        m_last_selection_mode = get_canvas().get_selection_mode();
        get_canvas().set_selection_mode(SelectionMode::NONE);
        ToolResponse r = m_core.tool_begin(m_drag_tool, args, true);
        tool_process(r);

        m_selection_for_drag.clear();
        m_drag_tool = ToolID::NONE;
    }
}
```

这里的关键点是：

- 拖动距离超过 10 像素
- `Editor` 自动调用 `m_core.tool_begin(..., true)`

第三个参数 `true` 表示：

- 这是一个 transient tool

所以这个场景的真实代码语义是：

- 用户没手动点工具栏
- 但 `Editor` 自动帮他开启了一个瞬时 `MOVE` tool


## 4. tool 激活后，后续鼠标移动为什么会实时更新

还是在 `Editor::handle_cursor_move()`：

```cpp
if (m_core.tool_is_active()) {
    ToolArgs args;
    args.type = ToolEventType::MOVE;
    ToolResponse r = m_core.tool_update(args);
    tool_process(r);
}
```

也就是说，一旦 `MOVE` tool 已经启动：

- 后续每次鼠标移动
- 都会变成一次 `ToolEventType::MOVE`
- 交给当前 tool 处理

所以“实时拖动”的本质是：

- GTK 不断发鼠标移动事件
- `Editor` 把它们持续转发给 `MOVE` tool


## 5. `ToolMove` 每一帧到底做了什么

代码在：

- `src/core/tools/tool_move.cpp`

关键逻辑是：

```cpp
if (args.type == ToolEventType::MOVE) {
    const auto delta = m_intf.get_cursor_pos() - m_inital_pos;
    for (auto [entity, point] : m_entities) {
        if (!entity->can_move(doc))
            continue;
        if (auto en_movable = dynamic_cast<IEntityMovable2D *>(entity)) {
            ...
            en_movable->move(en_last, delta2d, point);
        }
        else if (auto en_movable3d = dynamic_cast<IEntityMovable3D *>(entity)) {
            ...
            en_movable3d->move(en_last, delta, point);
        }
        ...
    }

    doc.set_group_solve_pending(m_first_group);
    m_core.solve_current(m_dragged_list);

    ...
    m_intf.set_first_update_group(m_first_group_render);
    return ToolResponse();
}
```

这段每帧做了三件大事：

### 5.1 先修改被拖对象的参数

对 2D 可移动对象：

```cpp
en_movable->move(en_last, delta2d, point);
```

对 3D 可移动对象：

```cpp
en_movable3d->move(en_last, delta, point);
```

注意这里不是改 OpenGL 顶点，而是改 `Document` 里的实体参数。

并且它不是基于“上一帧结果”继续叠加，而是基于拖动开始前的文档快照：

```cpp
auto &last_doc = m_core.get_current_last_document();
auto &en_last = *last_doc.m_entities.at(entity->m_uuid);
```

这样做的好处是：

- 计算稳定
- 不会每帧累积误差


### 5.2 标记从哪个 group 开始需要重新 solve

```cpp
doc.set_group_solve_pending(m_first_group);
```

意思是：

- 从相关 group 开始
- 约束和后续数据状态需要重新更新


### 5.3 立刻触发增量求解与更新

```cpp
m_core.solve_current(m_dragged_list);
```

而 `Core::solve_current(...)` 是：

- `src/core/core.cpp`

```cpp
void Core::solve_current(const DraggedList &dragged)
{
    if (!tool_is_active())
        throw std::runtime_error("to be called in tools only");
    auto &doc = get_current_document();
    doc.update_pending(get_current_group(), dragged);
}
```

所以拖动每一帧都会直接进入：

- `Document::update_pending(...)`

这就是“约束联动实时生效”的根源。


## 6. 为什么拖动时几何会根据约束实时变化

因为 `solve_current(...)` 走的是：

- `Document::update_pending(...)`

而你前面已经看过，里面是：

```cpp
if (index >= first_generate_index) {
    generate_group(*group);
}
if (index >= first_solve_index) {
    solve_group(*group, dragged);
}
if (index >= first_update_solid_model_index) {
    update_solid_model(*group);
}
```

也就是说拖动一帧时，实际在做：

```text
修改实体参数
  -> generate
  -> solve
  -> update_solid_model
```

所以你在界面上看到的是：

- 被拖对象位置变化
- 草图约束联动
- 后续实体模型也跟着更新

这不是渲染层的动画效果，而是文档真的被更新、求解、再重绘了。


## 7. 为什么拖动时画面会实时刷新

tool 更新后，`Editor::tool_process_one()` 会刷新画布：

- `src/editor/editor_tool.cpp`

```cpp
void Editor::tool_process_one()
{
    ...
    if (!m_no_canvas_update)
        canvas_update();
    get_canvas().set_selection(m_core.get_tool_selection(), false);
    ...
}
```

而 `canvas_update()` 最后会：

```cpp
get_canvas().request_push();
```

所以实时渲染链是：

```text
鼠标移动
  -> tool_update(MOVE)
  -> ToolMove 修改文档 + solve_current()
  -> Editor::canvas_update()
  -> Canvas::request_push()
  -> GTK 调 Canvas::on_render()
```

所以你看到的“实时渲染变换”，本质上是：

- 实时更新文档
- 实时重算
- 实时重绘


## 8. 为什么放手后还能 undo / redo

因为这个拖拽虽然是自动启动的 transient tool，但它最后仍然会正常 `commit`。

在 `ToolMove::update(...)` 里：

```cpp
else if (args.type == ToolEventType::ACTION) {
    switch (args.action) {
    case InToolActionID::LMB:
        return ToolResponse::commit();
    ...
    case InToolActionID::RMB:
    case InToolActionID::CANCEL:
        return ToolResponse::revert();
    }
}
```

也就是说：

- 左键确认 -> `commit`
- 右键/取消 -> `revert`

而 `Core::maybe_end_tool(...)` 在 `COMMIT` 时会：

```cpp
if (r.result == ToolResponse::Result::COMMIT) {
    const auto comment = "tool";
    rebuild_internal(false, comment);
    set_needs_save(true);
}
```

`rebuild_finish(...)` 又会：

```cpp
if (!from_undo) {
    m_documents.at(m_current_document).history_push(comment);
}
m_signal_rebuilt.emit();
```

也就是说，拖拽确认后：

- 会做一次正式 rebuild
- 会推一条 history item

所以它自然就能 `undo / redo`。


## 9. 为什么取消拖拽能回到原来状态

因为 tool 期间一直保留着“拖动开始前的文档快照”。

你前面已经看到：

```cpp
auto &last_doc = m_core.get_current_last_document();
```

而 `DocumentInfo::revert()` 是：

```cpp
void Core::DocumentInfo::revert()
{
    m_doc.reset();
    m_doc.emplace(get_last_document());
}
```

所以如果 tool 返回 `REVERT`：

- 文档会直接恢复到拖动前快照
- 然后再重建和重绘

因此取消拖拽可以完整回退。


## 10. `undo / redo` 本身怎么生效

`Core::undo()` / `Core::redo()` 都是基于 history manager 切换文档快照：

```cpp
void Core::undo()
{
    if (get_current_document_info().undo()) {
        fix_current_group();
        update_can_close();
        m_signal_rebuilt.emit();
        m_signal_needs_save.emit();
    }
}
```

```cpp
void Core::redo()
{
    if (get_current_document_info().redo()) {
        fix_current_group();
        update_can_close();
        m_signal_rebuilt.emit();
        m_signal_needs_save.emit();
    }
}
```

意思是：

- 切换到上一条 / 下一条文档快照
- 发 rebuilt 信号
- UI 和画布再按当前快照重绘

所以 undo/redo 的单位，本质上是：

- 一次已经 commit 的文档状态


## 11. 这个场景的代码级本质

你看到的是：

- 没点任何工具
- 直接拖对象
- 几何按约束联动
- 还能撤销重做

代码上的真实语义是：

```text
Editor 先侦测到拖拽意图
  -> 自动启动 transient MOVE tool
  -> ToolMove 每帧修改文档参数
  -> solve_current() -> update_pending()
  -> generate / solve / update_solid_model
  -> Editor 实时刷新画布
  -> commit 后写入 history
  -> undo / redo 基于 history 快照切换
```


## 12. 要害总结

- 表面上看像“没进工具直接拖”，实际上 `Editor` 会自动启动一个瞬时的 `MOVE` tool
- 进入拖拽的条件是：左键按下后鼠标移动超过阈值
- `ToolMove` 每一帧都会修改实体参数，并触发 `solve_current()`，所以约束会实时联动
- `solve_current()` 本质上走的是 `Document::update_pending()`，因此会继续触发 `generate -> solve -> update_solid_model`
- 每帧 tool 更新后，`Editor::tool_process_one()` 会调用 `canvas_update()`，所以画面实时刷新
- 左键确认后，tool 会 `commit`，并通过 `history_push("tool")` 形成一条可撤销的历史记录
- `undo / redo` 本质上是切换文档快照，再发 rebuilt 信号，让 UI 和画布重绘
