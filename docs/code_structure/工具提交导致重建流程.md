# 工具提交导致重建流程

这篇文档说明的是：

- 一个 tool 在提交（`COMMIT`）之后
- 代码如何一路走到文档重建
- 如何进入 `solid_model` 层
- 如何完成实体更新、三角化和最终渲染

为了更具体，这里以一个典型场景举例：

- 用户在草图里编辑几何
- tool 最终返回 `ToolResponse::commit()`
- 提交后触发整条重建链


## 1. 总体结论

`dune3d` 当前这条链的核心是：

```text
tool 返回 COMMIT
-> Core::maybe_end_tool()
-> Core::rebuild_internal()
-> Document::update_pending()
-> group.update_solid_model()
-> SolidModel::create(...)
-> SolidModelOcc::finish()
-> triangulate() / find_edges()
-> Core::rebuild_finish()
-> m_signal_rebuilt.emit()
-> Editor / Renderer 刷新
```

如果只记一句：

- tool 提交后，系统会先重建文档，再重建实体，再离散化，最后刷新 UI 和画布


## 2. 起点：tool 返回 `COMMIT`

很多草图/编辑类 tool 在完成时都会返回：

```cpp
return ToolResponse::commit();
```

例如：

- `tool_move.cpp`
- `tool_draw_circle_2d.cpp`
- `tool_draw_rectangle.cpp`
- `tool_draw_contour.cpp`

以拖拽编辑为例，`ToolMove` 里有：

`src/core/tools/tool_move.cpp`

```cpp
case InToolActionID::LMB:
    return ToolResponse::commit();
```

意思是：

- 用户确认这次编辑
- tool 告诉 core：这次修改需要正式提交


## 3. `Core::maybe_end_tool()`：提交后的总入口

`src/core/core.cpp`

```cpp
bool Core::maybe_end_tool(const ToolResponse &r)
{
    if (r.result != ToolResponse::Result::NOP) {
        m_last_tool_selection = m_tool->m_selection;
        m_tool.reset();
        m_signal_tool_changed.emit();
        if (r.result == ToolResponse::Result::COMMIT) {
            const auto comment = "tool";
            rebuild_internal(false, comment);
            set_needs_save(true);
        }
        else if (r.result == ToolResponse::Result::REVERT) {
            get_current_document_info().revert();
            rebuild_internal(true, "undo");
        }
        return true;
    }
    return false;
}
```

这里对 `COMMIT` 的核心动作是：

```cpp
rebuild_internal(false, comment);
```

所以从这一步开始，进入正式的“提交后重建”阶段。


## 4. `rebuild_internal()`：触发文档重建

`src/core/core.cpp`

```cpp
void Core::rebuild_internal(bool from_undo, const std::string &comment)
{
    if (!has_documents())
        return;
    fix_current_group();
    for (auto &[uu, en] : get_current_document().m_entities) {
        en->m_selection_invisible = false;
    }
    get_current_document().update_pending();
    update_can_close();
    rebuild_finish(from_undo, comment);
}
```

这里最关键的是：

```cpp
get_current_document().update_pending();
```

注意它没有传 `last_group_to_update`，意味着：

- 从当前 pending 起点开始
- 一路重建到需要更新的所有后续 group

这就是“tool 提交后为什么会触发后续实体链重建”的主入口。


## 5. `Document::update_pending()`：文档级重建主循环

`src/document/document.cpp`

```cpp
void Document::update_pending(const UUID &last_group_to_update_i, const std::vector<EntityAndPoint> &dragged)
{
    ...
    if (m_first_group_generate) {
        for (auto group : groups_sorted) {
            ...
            if (index >= first_generate_index) {
                generate_group(*group);
            }
        }
        erase_invalid();
    }

    for (auto group : groups_sorted) {
        ...
        if (index >= first_solve_index) {
            solve_group(*group, dragged);
        }
        if (index >= first_update_solid_model_index) {
            update_solid_model(*group);
        }
    }
    ...
}
```

这一步分三段：

### 5.1 `generate_group(*group)`

- 生成派生 entity
- 例如某些特征会自动生成辅助几何

### 5.2 `solve_group(*group, dragged)`

- 跑约束求解
- 把草图/约束的结果写回文档参数

### 5.3 `update_solid_model(*group)`

- 对实现了 `IGroupSolidModel` 的 group
- 进入实体更新逻辑

所以 `update_pending()` 就是整个文档重建的中心调度器。


## 6. 进入实体层：`Document::update_solid_model()`

`src/document/document.cpp`

```cpp
void Document::update_solid_model(Group &group)
{
    if (auto gr = dynamic_cast<IGroupSolidModel *>(&group))
        gr->update_solid_model(*this);
}
```

这里会把控制权交给具体 group。

例如对于 `Extrude`：

`src/document/group/group_extrude.cpp`

```cpp
void GroupExtrude::update_solid_model(const Document &doc)
{
    m_solid_model = SolidModel::create(doc, *this);
}
```

也就是说：

- group 层只负责发起
- 真正 OCC 建模在 `solid_model` 目录里做


## 7. 以 `Extrude` 为例：进入 `solid_model` 目录

`src/document/solid_model/solid_model_extrude.cpp`

```cpp
std::shared_ptr<const SolidModel> SolidModel::create(const Document &doc, GroupExtrude &group)
{
    group.m_sweep_messages.clear();
    auto mod = std::make_shared<SolidModelOcc>();
    ...
    auto face_builder = FaceBuilder::from_document(doc, group.m_wrkpl, group.m_source_group, offset);
    ...
    mod->m_shape = BRepPrimAPI_MakePrism(face_builder.get_faces(), gp_Vec(dvec.x, dvec.y, dvec.z));
    ...
    if (!mod->update_acc_finish(doc, group)) {
        ...
        return nullptr;
    }

    return mod;
}
```

这一步做了几件事：

### 7.1 从文档草图构建 OCC face

```cpp
auto face_builder = FaceBuilder::from_document(doc, group.m_wrkpl, group.m_source_group, offset);
```

### 7.2 用 OCC 做拉伸

```cpp
mod->m_shape = BRepPrimAPI_MakePrism(face_builder.get_faces(), gp_Vec(dvec.x, dvec.y, dvec.z));
```

此时：

- `mod->m_shape` 是“当前这个 extrude 特征自己的 shape”

但还不是整个 body 的累计实体结果。


## 8. `SolidModelOcc::update_acc_finish()`：接到实体链上

`src/document/solid_model/solid_model_occ.cpp`

```cpp
bool SolidModelOcc::update_acc_finish(const Document &doc, const Group &group)
{
    auto operation = dynamic_cast<const IGroupSolidModel &>(group).get_operation();
    const auto last_solid_model = dynamic_cast<const SolidModelOcc *>(get_last_solid_model(doc, group));
    update_acc(operation, last_solid_model);

    if (m_shape_acc.IsNull()) {
        return false;
    }

    finish(doc, group);

    return true;
}
```

这里做两件核心工作：

### 8.1 找前一个实体结果

```cpp
const auto last_solid_model = dynamic_cast<const SolidModelOcc *>(get_last_solid_model(doc, group));
```

它会在：

- 当前 body 内
- 按 group 顺序

找到当前 group 前面最近一个有效实体结果。

### 8.2 生成累计实体 `m_shape_acc`

```cpp
update_acc(operation, last_solid_model);
```

如果没有前驱：

- `m_shape_acc = m_shape`

如果有前驱：

- 当前 `m_shape` 接到前一个 `m_shape_acc` 后面

所以这里完成的是：

- 当前特征结果
-> 接入整个 body 实体历史链


## 9. 离散化：`finish()` -> `triangulate()` / `find_edges()`

`src/document/solid_model/solid_model_occ.cpp`

```cpp
void SolidModelOcc::finish(const Document &doc, const Group &group)
{
    ...
    triangulate();
    find_edges();
}
```

### 9.1 三角化

```cpp
void SolidModelOcc::triangulate()
{
    m_faces.clear();
    Triangulator tri{m_shape_acc, m_color, m_faces};
}
```

作用：

- 把 `TopoDS_Shape`
- 转成渲染器使用的 `m_faces`

### 9.2 提边

```cpp
void SolidModelOcc::find_edges()
{
    m_edges.clear();
    TopExp_Explorer topex(m_shape_acc, TopAbs_EDGE);
    ...
}
```

作用：

- 提取边的离散数据
- 给选边/线框等功能使用

也就是说：

- 实体更新完成后
- 会立刻做离散化和边缓存生成


## 10. 重建结束：`rebuild_finish()`

`src/core/core.cpp`

```cpp
void Core::rebuild_finish(bool from_undo, const std::string &comment)
{
    if (!from_undo) {
        m_documents.at(m_current_document).history_push(comment);
    }
    m_signal_rebuilt.emit();
}
```

这里做两件事：

### 10.1 历史入栈

```cpp
m_documents.at(m_current_document).history_push(comment);
```

### 10.2 发出“重建完成”信号

```cpp
m_signal_rebuilt.emit();
```


## 11. rebuild 信号之后：UI 刷新

这个信号会触发多个 Editor 层刷新逻辑。

例如：

`src/editor/editor.cpp`

```cpp
m_core.signal_rebuilt().connect([this] {
    if (m_group_editor) {
        if (m_core.get_current_group() != m_group_editor->get_group())
            update_group_editor();
        else
            m_group_editor->reload();
    }
});
```

刷新 group editor。

---

`src/editor/editor.cpp`

```cpp
m_core.signal_rebuilt().connect(
        [this] { Glib::signal_idle().connect_once([this] { m_constraints_box->update(); }); });
```

刷新 constraints box。

---

`src/editor/editor_workspace_browser.cpp`

```cpp
m_core.signal_rebuilt().connect([this] {
    Glib::signal_idle().connect_once([this] {
        if (!m_current_workspace_view)
            return;
        m_workspace_browser->update_documents(m_workspace_views.at(m_current_workspace_view).m_documents);
    });
});
```

刷新左侧 workspace browser / group tree。


## 12. 最终渲染：Renderer 使用缓存结果绘制

Renderer 并不会再次从 OCC shape 做三角化，而是直接用刚才已经准备好的缓存。

`src/render/renderer.cpp`

```cpp
if (gr->get_solid_model()) {
    last_solid_model = gr->get_solid_model();
    last_solid_model_group = group;
}
```

最终绘制：

```cpp
m_ca.add_face_group(last_solid_model->m_faces, {0, 0, 0},
                    glm::quat_identity<float, glm::defaultp>(), color);
```

也就是说：

- 离散化发生在 `SolidModelOcc::finish()`
- Renderer 只是消费 `m_faces / m_edges`


## 13. 一个具体例子：`ToolMove` 提交后触发重建

拿草图中拖动点为例：

### 13.1 用户拖动时

`ToolMove` 在移动过程中会做局部更新：

`src/core/tools/tool_move.cpp`

```cpp
doc.set_group_solve_pending(m_first_group);
m_core.solve_current(m_dragged_list);
```

这里还是局部更新，只到当前 group。

### 13.2 用户左键确认

```cpp
case InToolActionID::LMB:
    return ToolResponse::commit();
```

### 13.3 提交后

```text
ToolMove::update()
-> return ToolResponse::commit()
-> Core::maybe_end_tool()
-> rebuild_internal(false, "tool")
-> Document::update_pending()
-> 后续 group 的 generate / solve / update_solid_model 全跑
-> SolidModelOcc::finish()
-> triangulate() / find_edges()
-> rebuild_finish()
-> signal_rebuilt
-> UI 刷新
-> Renderer 使用 m_faces 绘制
```

这就是为什么：

- 草图编辑一提交
- 后面复杂实体链也可能跟着重建、离散化、重绘


## 14. 总结

从 tool 提交到几何重建渲染，当前代码的主路径是：

```text
ToolResponse::commit()
-> Core::maybe_end_tool()
-> Core::rebuild_internal()
-> Document::update_pending()
-> Group::update_solid_model()
-> SolidModel::create(...)
-> SolidModelOcc::update_acc_finish()
-> SolidModelOcc::finish()
-> triangulate() / find_edges()
-> Core::rebuild_finish()
-> m_signal_rebuilt.emit()
-> Editor/UI 刷新
-> Renderer 使用缓存结果渲染
```

如果只记一句：

- tool 提交后，系统不是只“保存修改”，而是会走完整的文档重建、实体更新、离散化和 UI 刷新流程
