# 点击特征树重新渲染逻辑

这篇文档回答一个具体问题：

- 为什么点左侧特征树里的 `Sketch 2` 和点 `Extrude 2`，右侧 area 会显示不同内容

先说结论：

- 这里通常不是“重新修改文档参数”
- 而是“切换 current group”
- `Renderer` 会把当前显示截断到这个 group
- 所以你看到的是“历史树不同阶段”的模型与草图内容


## 1. 先说总体链路

点击左侧特征树某个 group 后，主链是：

```text
WorkspaceBrowser 选中某个 group
-> Editor::on_workspace_browser_group_selected()
-> Editor::set_current_group()
-> CanvasUpdater 析构
-> Editor::canvas_update_keep_selection()
-> Editor::canvas_update()
-> Editor::render_document()
-> Renderer::render(doc, current_group, ...)
-> 按 current_group 决定显示哪些 group / solid model / 约束
-> Canvas::request_push()
```

如果只记一句：

- 点特征树，本质是在切换“当前看到历史树的哪一步”


## 2. 左侧树选中 group 时，先发出 group selected 信号

`WorkspaceBrowser` 用 `Gtk::SingleSelection` 监听树节点选中变化。

`src/editor/workspace_browser.cpp`

```cpp
m_selection_model->signal_selection_changed().connect([this](guint, guint) {
    auto sel = m_selection_model->get_selected_item();
    auto tr = std::dynamic_pointer_cast<Gtk::TreeListRow>(sel);
    if (!tr)
        return;
    if (auto gr = std::dynamic_pointer_cast<WorkspaceBrowser::GroupItem>(tr->get_item())) {
        m_signal_group_selected.emit(gr->m_doc, gr->m_uuid);
    }
});
```

意思是：

- 你点了树里某个 group
- `WorkspaceBrowser` 发出：
  - 选中了哪个 document
  - 选中了哪个 group


## 3. `Editor` 收到信号后切换 current group

信号连接在：

`src/editor/editor_workspace_browser.cpp`

```cpp
m_workspace_browser->signal_group_selected().connect(
        sigc::mem_fun(*this, &Editor::on_workspace_browser_group_selected));
```

进入：

```cpp
void Editor::on_workspace_browser_group_selected(const UUID &uu_doc, const UUID &uu_group)
{
    if (m_core.tool_is_active())
        return;
    auto &idoc = m_core.get_current_idocument_info();
    if (idoc.get_uuid() == uu_doc && idoc.get_current_group() == uu_group)
        return;
    m_core.set_current_document(uu_doc);
    m_workspace_views.at(m_current_workspace_view).m_current_document = uu_doc;
    update_version_info();
    get_current_document_view().m_current_group = uu_group;
    set_current_group(uu_group);
}
```

这里最关键的是：

```cpp
get_current_document_view().m_current_group = uu_group;
set_current_group(uu_group);
```

说明点击树节点后，真正发生的是：

- 当前 workspace view 的 current group 改了
- `Editor` 进入“切换当前 group”的刷新逻辑


## 4. `set_current_group()` 不一定重建文档，但一定会触发画布刷新

`src/editor/editor.cpp`

```cpp
void Editor::set_current_group(const UUID &uu_group)
{
    CanvasUpdater canvas_updater{*this};

    m_core.set_current_group(uu_group);
    m_workspace_browser->update_current_group(get_current_document_views());
    update_workplane_label();
    m_constraints_box->update();
    update_group_editor();
    update_action_sensitivity();
    update_action_bar_buttons_sensitivity();
    update_selection_editor();
}
```

这里第一句非常关键：

```cpp
CanvasUpdater canvas_updater{*this};
```

它的析构函数会在函数结束时自动触发画布刷新：

```cpp
Editor::CanvasUpdater::~CanvasUpdater()
{
    ...
    if (m_editor.m_canvas_update_pending == 0)
        m_editor.canvas_update_keep_selection();
}
```

所以点击特征树后：

- 先切 current group
- 再自动 `canvas_update_keep_selection()`


## 5. 真正重绘入口是 `canvas_update()`

`src/editor/editor.cpp`

```cpp
void Editor::canvas_update_keep_selection()
{
    auto sel = get_canvas().get_selection();
    canvas_update();
    get_canvas().set_selection(sel, false);
}
```

然后：

```cpp
void Editor::canvas_update()
{
    ...
    if (m_core.has_documents())
        render_document(m_core.get_current_idocument_info());

    get_canvas().set_hover_selection(hover_sel);
    update_error_overlay();
    get_canvas().request_push();
    m_update_groups_after = UUID();
}
```

这里的含义是：

- 清理当前 canvas 内容
- 重新调用 `render_document()`
- 最后 `request_push()` 请求真正呈现


## 6. `render_document()` 把 current group 传给 Renderer

`src/editor/editor.cpp`

```cpp
void Editor::render_document(const IDocumentInfo &doc)
{
    ...
    Renderer renderer(get_canvas(), m_core);
    ...
    renderer.render(doc.get_document(), doc.get_current_group(), doc_view,
                    m_workspace_views.at(m_current_workspace_view), doc.get_dirname(), sr);
}
```

这里最关键的是第二个参数：

```cpp
doc.get_current_group()
```

这说明：

- `Renderer` 每次渲染时都知道当前 group 是谁
- 你点 `Sketch 2` 和点 `Extrude 2`，传进去的 `current_group` 就不同


## 7. `Renderer` 会把显示截断到 current group

最关键的判断在：

`src/render/renderer.cpp`

```cpp
bool Renderer::group_is_visible(const UUID &uu) const
{
    if (m_current_group->m_uuid == uu)
        return true;
    auto &group = m_doc->get_group(uu);
    if (group.get_index() > m_current_group->get_index())
        return false;
    if (!m_doc_view->group_is_visible(uu))
        return false;
    auto body = group.find_body(*m_doc);
    if (m_current_body_group != &body.group && !m_doc_view->body_is_visible(body.group.m_uuid))
        return false;
    return true;
}
```

翻成人话：

- 当前 group 一定可见
- 但排在 current group 后面的 group 不可见

这就是“点树节点后显示不同内容”的第一核心原因。

也就是说：

- 点 `Sketch 2` 时，`Extrude 2` 这种后续 group 不会显示
- 点 `Extrude 2` 时，它自己也进入可见范围


## 8. 实体 solid model 也只显示到 current group 为止

`Renderer::render()` 里对每个 body 会找“截至 current group 的最后一个 solid model”：

`src/render/renderer.cpp`

```cpp
for (auto body_groups : groups_by_body) {
    ...
    const SolidModel *last_solid_model = nullptr;
    const Group *last_solid_model_group = nullptr;
    for (auto group : body_groups.groups) {
        if (!group_is_visible(group->m_uuid))
            continue;
        if (auto gr = dynamic_cast<const IGroupSolidModel *>(group)) {
            if (gr->get_solid_model()) {
                last_solid_model = gr->get_solid_model();
                last_solid_model_group = group;
            }
            if (group->m_uuid == current_group)
                break;
        }
    }
    ...
    m_ca.add_face_group(last_solid_model->m_faces, ...)
}
```

意思是：

- 只统计当前 body 里、在 current group 之前或等于 current group 的 solid model
- 一旦走到 current group 就停

所以：

- 点 `Sketch 2` 时，`Extrude 2` 的实体结果不会进入 area
- 点 `Extrude 2` 时，body 最终实体就推进到了 `Extrude 2`


## 9. 当前 group 还会影响约束、草图元素、工作平面的显示方式

### 9.1 只画当前 group 的约束

`src/render/renderer.cpp`

```cpp
if (!sr) {
    set_chunk_from_group(*m_current_group);
    for (const auto &[uu, el] : doc.m_constraints) {
        if (m_current_group->m_uuid != el->m_group)
            continue;
        el->accept(*this);
    }
    draw_constraints();
}
```

所以：

- 点 `Sketch 2` 时，当前约束显示的是 `Sketch 2` 的
- 点 `Extrude 2` 时，就不再把 `Sketch 2` 当成当前约束组


### 9.2 当前 group 的实体显示为 active，之前组的是 inactive

`src/render/renderer.cpp`

```cpp
m_ca.set_vertex_inactive(entity.m_group != m_current_group->m_uuid);
```

所以：

- 当前组的草图点线更像“正在编辑”
- 历史组的元素会以非当前态显示


### 9.3 工作平面也跟 current group 关联

`src/render/renderer.cpp`

```cpp
if (m_workspace_view->hide_irrelevant_workplanes()) {
    if (wrkpl.m_group != m_current_group->m_uuid && wrkpl.m_uuid != m_current_group->m_active_wrkpl)
        return;
}
```

以及：

```cpp
if (wrkpl.m_uuid == m_current_group->m_active_wrkpl) {
    ...
}
```

所以：

- 当前 group 的 active workplane 会被特别显示
- 不相关的 workplane 可能被隐藏


## 10. 这和 `DocumentView` 有什么关系

`DocumentView` 里保存了每个 workspace view 的显示状态，包括：

- `m_current_group`
- `m_group_views`
- `m_body_views`

`src/workspace/document_view.hpp`

```cpp
UUID m_current_group;
std::map<UUID, GroupView> m_group_views;
std::map<UUID, BodyView> m_body_views;
```

这些状态会被 `Renderer` 用来进一步判断：

- 某个 group 是否被手动隐藏
- 某个 body 是否可见
- 某个 body 的 solid model 是否可见

但最核心的“显示到哪一步”，仍然是由 `current_group` 决定。


## 11. 一个具体例子

假设左侧树顺序是：

```text
Reference
Sketch 1
Extrude 1
Linear array 1
Sketch 2
Extrude 2
```

### 情况 A：点 `Sketch 2`

这时 `current_group = Sketch 2`。

Renderer 的效果大致是：

- `Reference / Sketch 1 / Extrude 1 / Linear array 1 / Sketch 2` 可见
- `Extrude 2` 不可见，因为它在当前组之后
- 当前约束按 `Sketch 2` 画
- 当前工作平面按 `Sketch 2` 的上下文显示
- body 的最终实体结果最多到 `Sketch 2` 之前那一步

### 情况 B：点 `Extrude 2`

这时 `current_group = Extrude 2`。

Renderer 的效果大致是：

- `Extrude 2` 自己也进入可见范围
- body 的实体结果推进到 `Extrude 2`
- 当前约束/当前编辑态切换到 `Extrude 2`
- active workplane 和高亮语义也跟着切换

所以右侧 area 会明显不同。


## 12. 总结

- 点击左侧特征树节点，首先发生的是 current group 切换
- `Editor::set_current_group()` 不一定重建文档，但一定会触发 canvas 刷新
- `Renderer::render()` 会拿到新的 `current_group`
- `Renderer` 的可见性规则决定了：排在 current group 后面的 group 不显示
- 实体 solid model 也只显示到 current group 为止
- 当前约束、草图激活态、工作平面显示方式也都依赖 current group

所以一句话：

- 点击特征树并不是简单“选中一行”，而是在切换“当前查看的建模阶段”，右侧 area 显示的是该阶段对应的历史截面
