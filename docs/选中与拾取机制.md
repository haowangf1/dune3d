# 选中与拾取机制

这篇只讲一个问题：

- 这个项目是怎么判断“鼠标现在选中了什么”的

重点抓 5 件事：

- 选中的逻辑单位是什么
- 渲染时怎么把图元绑定到这个单位
- 鼠标怎么从屏幕像素反查到业务对象
- 点击 / 框选 / 重叠对象时怎么决定最终选中结果
- 选中结果最后怎么被 UI 和 tool 使用


## 1. 先说结论：选中的单位不是 OpenGL 顶点

这个项目真正的选中单位是：

- `SelectableRef`

定义在：

- `src/canvas/selectable_ref.hpp`

```cpp
class SelectableRef {
public:
    enum class Type { ENTITY, CONSTRAINT, SOLID_MODEL_EDGE, DOCUMENT };
    Type type;
    UUID item;
    unsigned int point;
    ...
};
```

所以这个项目的选中，不是“选中某个 GPU 顶点”，而是选中一个业务对象引用。

这 3 个字段含义是：

- `type`
  - 选中的对象类别
- `item`
  - 对应对象 UUID
- `point`
  - 对应对象上的哪个点/哪个子编号


## 2. 选中的对象类型有哪些

从 `SelectableRef::Type` 看，主要有 4 类：

### 2.1 `ENTITY`

最常见。

例如：

- 线本体
- 线端点
- 圆心
- 工作平面
- 图片
- 文本

这类选中时通常是：

- `item = entity UUID`
- `point = 0/1/2/...`

例如渲染一条线时：

```cpp
m_ca.add_selectable(m_ca.draw_line(line.m_p1, line.m_p2),
                    SelectableRef{SelectableRef::Type::ENTITY, line.m_uuid, 0});
m_ca.add_selectable(m_ca.draw_point(line.m_p1),
                    SelectableRef{SelectableRef::Type::ENTITY, line.m_uuid, 1});
m_ca.add_selectable(m_ca.draw_point(line.m_p2),
                    SelectableRef{SelectableRef::Type::ENTITY, line.m_uuid, 2});
```

也就是说：

- `point = 0` 往往表示实体本体
- `point = 1/2/...` 表示实体上的特定点


### 2.2 `CONSTRAINT`

约束本身也可以被选中。

例如约束可视图元会绑定成：

```cpp
m_ca.add_selectable(vr, SelectableRef{SelectableRef::Type::CONSTRAINT, constraint.constraint, 0});
```


### 2.3 `SOLID_MODEL_EDGE`

用于实体边选择模式。

例如：

```cpp
m_ca.add_selectable(m_ca.draw_line(path.at(i - 1), path.at(i)),
                    SelectableRef{SelectableRef::Type::SOLID_MODEL_EDGE, UUID(), edge_idx});
```

这里 `point` 被拿来存 edge 编号。


### 2.4 `DOCUMENT`

用于多文档场景下把整份文档作为一个可选对象。


## 3. `point` 字段为什么重要

对 `ENTITY` 类型尤其重要。

它不是泛泛的“点”，而是：

- 这个实体上哪个可选子部位

例如：

- `0`：实体本体
- `1 / 2 / 3`：端点、圆心、控制点等

并且它还能直接转换成约束系统常用的 `EntityAndPoint`：

```cpp
EntityAndPoint SelectableRef::get_entity_and_point() const
{
    if (type != Type::ENTITY)
        throw std::runtime_error("not an entity");
    return EntityAndPoint{item, point};
}
```

这说明：

- 选中系统和约束系统是直接对接的


## 4. 渲染时怎么把图元绑定到 `SelectableRef`

这一步发生在渲染阶段。

`Renderer` 在画每个可交互图元时，会调用：

- `Canvas::add_selectable(...)`

例如：

```cpp
m_ca.add_selectable(m_ca.draw_line(p1, p2), SelectableRef{SelectableRef::Type::ENTITY, line.m_uuid, 0});
```

而 `Canvas::add_selectable(...)` 是：

```cpp
void Canvas::add_selectable(const VertexRef &vref, const SelectableRef &sref)
{
    if (vref.type == VertexType::SELECTION_INVISIBLE)
        return;
    SelectableRef sr = sref;
    if (m_override_selectable.has_value())
        sr = m_override_selectable.value();
    m_vertex_to_selectable_map.emplace(vref, sr);
    m_selectable_to_vertex_map[sr].push_back(vref);
}
```

这里维护了两张关键映射表：

### 4.1 `m_vertex_to_selectable_map`

- `VertexRef -> SelectableRef`

作用：

- 从渲染图元反查业务对象

### 4.2 `m_selectable_to_vertex_map`

- `SelectableRef -> [VertexRef...]`

作用：

- 从业务对象反查它对应的所有渲染图元

所以这套机制的核心是：

```text
屏幕图元 <-> 业务对象
```


## 5. 鼠标是怎么从像素反查到对象的

这里走的是 pick buffer 机制。

不是直接做 CPU 几何求交，而是：

- 渲染一份 picking buffer
- 每个像素保存一个 pick id
- 鼠标位置去读这个 pick id
- 再映射回 `SelectableRef`


### 5.1 从像素读 pick id

```cpp
Canvas::pick_buf_t Canvas::read_pick_buf(const std::vector<pick_buf_t> &pick_buf, int x, int y) const
{
    int xi = x * m_scale_factor;
    int yi = y * m_scale_factor;
    if (xi >= m_dev_width || yi >= m_dev_height || x < 0 || y < 0)
        return 0;
    const int idx = ((m_dev_height)-yi - 1) * m_dev_width + xi;
    return pick_buf.at(idx);
}
```

这一步只是在取：

- 鼠标当前像素对应的 pick 编号


### 5.2 pick id -> VertexRef -> SelectableRef

```cpp
std::optional<SelectableRef> Canvas::get_selectable_ref_for_pick(unsigned int pick) const
{
    if (!pick)
        return {};
    return get_selectable_ref_for_vertex_ref(get_vertex_ref_for_pick(pick));
}
```

再往下：

```cpp
std::optional<SelectableRef> Canvas::get_selectable_ref_for_vertex_ref(const VertexRef &vref) const
{
    if (m_vertex_to_selectable_map.contains(vref)) {
        auto sr = m_vertex_to_selectable_map.at(vref);
        if (!m_selection_filter || m_selection_filter->can_select(sr))
            return sr;
        else
            return {};
    }
    else {
        return {};
    }
}
```

所以真正的反查链是：

```text
鼠标像素
  -> pick id
  -> VertexRef
  -> SelectableRef
```


## 6. hover 是怎么判定的

hover 逻辑在：

- `Canvas::update_hover_selection()`

```cpp
void Canvas::update_hover_selection()
{
    if (m_vertex_type_picks.size() == 0)
        return;
    if (m_selection_mode != SelectionMode::NONE) {
        auto last_hover_selection = m_hover_selection;
        m_hover_selection.reset();
        auto pick = get_hover_pick();

        if (auto sr = get_selectable_ref_for_pick(pick))
            m_hover_selection = *sr;

        if (m_hover_selection != last_hover_selection) {
            ...
            m_signal_hover_selection_changed.emit();
        }
    }
}
```

意思：

- 每次鼠标移动
- 先取当前 hover pick
- 再映射成 `SelectableRef`
- 更新 `m_hover_selection`


### 6.1 hover 不是只看单个像素

`get_hover_pick(...)` 里有一段附近搜索逻辑：

```cpp
auto pick = read_pick_buf(pick_buf, m_last_x, m_last_y);
if (!pick || any_of(get_vertex_ref_for_pick(pick).type, VertexType::FACE_GROUP, VertexType::PICTURE)) {
    int box_size = 10;
    ...
    for (int dx = -box_size; dx <= box_size; dx++) {
        for (int dy = -box_size; dy <= box_size; dy++) {
            ...
        }
    }
}
```

这说明：

- 如果当前像素下没有命中，或者命中的是 face/picture
- 系统会在附近找最近的线/点类对象

这让 CAD 编辑时更容易 hover 到细线和端点。


## 7. 点击后怎么形成“选中集合”

点击释放逻辑在：

- `Canvas::handle_click_release()`

正常点击时：

```cpp
else if (m_selection_mode == SelectionMode::NORMAL) {
    if (m_hover_selection.has_value()) {
        ...
        auto sel = get_selection();
        if (sel.contains(m_hover_selection.value())) {
            sel.erase(m_hover_selection.value());
        }
        else {
            sel.insert(m_hover_selection.value());
        }
        set_selection(sel, true);
    }
    else {
        set_selection({}, true);
    }
}
```

意思：

- 当前 hover 对象就是点击候选
- 如果已经在选中集合里，就取消
- 否则加入

所以这个项目里的当前 selection 本质上是：

- `std::set<SelectableRef>`


## 8. 框选怎么做

框选逻辑在：

- `Canvas::update_drag_selection(...)`

先遍历框内像素：

```cpp
for (int x = x0; x <= x1; x++) {
    for (int y = y0; y <= y1; y++) {
        const bool is_border = (x == x0) || (x == x1) || (y == y0) || (y == y1);
        const auto pick = read_pick_buf(m_pick_buf, x, y);
        if (pick) {
            if (is_border)
                picks_border.insert(pick);
            else
                picks.insert(pick);
        }
    }
}
```

然后转成 `SelectableRef`：

```cpp
for (const auto pick : picks) {
    if (auto sr = get_selectable_ref_for_pick(pick))
        sel.insert(*sr);
}
for (const auto pick : picks_border) {
    if (auto sr = get_selectable_ref_for_pick(pick))
        sel.erase(*sr);
}
set_selection(sel, false);
```

这套逻辑的效果接近：

- 框内部的对象加入
- 边界擦到的对象移除

也就是偏向“只选完全在框内的对象”。


## 9. 重叠对象时怎么选

这里用了 selection peeling。

相关逻辑在：

- `Canvas::peel_selection()`

它会把当前像素下的重叠候选一层层剥出来，收集成 `srv_list`：

```cpp
const auto vref = get_vertex_ref_for_pick(pick);
const auto sr = get_selectable_ref_for_vertex_ref(vref);
...
srv_list.emplace_back(vref.type, sr);
```

然后：

- 如果只有一个候选，直接选
- 如果有多个候选，就弹选择菜单

例如：

```cpp
if (srv_list.size() == 1) {
    need_menu = false;
    the_selectable = srv_list.front().selectable;
}
...
if (need_menu) {
    auto buttons = m_selection_menu_creator->create(*m_selection_menu, srv_list);
    ...
}
```

所以这个项目不是简单地“谁在最前面就选谁”，而是支持：

- 多层对象重叠后的候选选择


## 10. 选中后为什么会高亮

`Canvas::set_selection(...)` 会把选中集合对应的图元打上 flag：

```cpp
void Canvas::set_selection(const std::set<SelectableRef> &sel, bool emit)
{
    set_flag_for_selectables(sel, VertexFlags::SELECTED);
    if (emit)
        m_signal_selection_changed.emit();
}
```

而 `set_flag_for_selectables(...)` 会利用：

- `m_selectable_to_vertex_map`

把一个 `SelectableRef` 找回对应的所有 `VertexRef`，然后给这些图元打 `SELECTED` 标志。

所以高亮机制是：

```text
SelectableRef
  -> 反查所有关联图元
  -> 给这些图元打 SELECTED / HOVER flag
  -> 重新绘制
```


## 11. `selection_invisible` 是什么

有些对象可以画出来，但不参与正常选择。

渲染时会设置：

```cpp
m_ca.set_selection_invisible(entity.m_selection_invisible);
```

这样这些图元虽然显示出来，但不会进入正常的 selectable 映射。

这常用于：

- 临时预览对象
- 一些辅助几何
- 不希望干扰选择的构造显示


## 12. 选中结果最后怎么被工具使用

最终 selection 是：

- `std::set<SelectableRef>`

后续 tool 会按自己的语义去解释它。

例如：

- 约束工具会把它解析成 `EntityAndPoint`
- 实体边工具要求它是 `SOLID_MODEL_EDGE`
- 选旋转轴工具要求它是某种 `ENTITY`

所以可以把整个机制分成两层：

### Canvas 层

负责：

- 屏幕 picking
- `SelectableRef` 判定
- hover / click / drag / peeling

### Editor / Core / Tool 层

负责：

- 解释这个 `SelectableRef` 在当前操作里意味着什么


## 13. 一条完整主链

把整个项目的选中机制压缩成一条：

```text
Renderer 渲染可交互图元
  -> 给图元绑定 SelectableRef
  -> Canvas 建立 VertexRef <-> SelectableRef 映射

鼠标移动
  -> 读 pick buffer
  -> 像素 -> pick id -> VertexRef -> SelectableRef
  -> 更新 hover_selection

鼠标点击
  -> 用 hover_selection 更新 selection 集合

框选
  -> 读框内 pick buffer
  -> 收集多个 SelectableRef
  -> 更新 selection 集合

重叠对象
  -> selection peeling
  -> 直接选 or 弹选择菜单

选中后
  -> 根据 SelectableRef 找到相关图元
  -> 打 SELECTED / HOVER flag
  -> 重绘

工具层
  -> 消费 selection 集合
  -> 解释这些 SelectableRef 的业务语义
```


## 14. 要害总结

- 这个项目真正的选中单位是 `SelectableRef`，不是 OpenGL 顶点
- `SelectableRef` 由 `type + item + point` 组成，能表达实体本体、实体上的点、约束、solid model edge 等对象
- 渲染时每个可交互图元都会通过 `add_selectable(...)` 绑定到一个 `SelectableRef`
- 鼠标 picking 的核心链是：像素 -> pick id -> VertexRef -> SelectableRef
- hover 会做附近搜索，优先帮助用户命中线和点
- selection 是一个 `std::set<SelectableRef>`，点击、框选、重叠选择最终都会落到这个集合
- 高亮不是直接选图元，而是先选 `SelectableRef`，再反查所有关联图元打 flag
- Canvas 负责“判定选中了谁”，Editor / Core / Tool 负责“解释这个选中结果意味着什么”
