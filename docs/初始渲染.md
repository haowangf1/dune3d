# 初始渲染

这篇只讲一个问题：

- 软件打开后，中间那个 3D 视图窗口里看到的内容，是怎么一步步出来的

重点只抓 4 类东西：

- 主视图窗口本体
- 3D 草图/线框
- 工作平面可视化（你看到的组标轴、平面框、法向指示）
- 角落的小方向方块


## 1. 先分清两个 `render`

代码里有两个容易混的“render”：

- `Renderer::render(...)`：项目自己写的“场景整理器”，负责决定画什么
- `Canvas::on_render(...)`：GTK/OpenGL 那层真正开始画这一帧

可以直接这样记：

- `Renderer`：把 `Document` 里的实体翻成“待绘制数据”
- `Canvas`：把这些数据真正画到 OpenGL 画布上


## 2. 主视图窗口本体是谁

主视图就是 `Canvas`，它是项目自己封装的 GTK OpenGL 控件。

它不是普通 `Gtk::Widget`，而是继承自 `Gtk::GLArea`，也就是“GTK 提供一块能画 OpenGL 的区域，项目自己接管绘制”。

你可以把它理解成：

- GTK 提供窗口、事件循环、GL context
- `Canvas` 提供 CAD 视图自己的渲染逻辑

真正每帧开始绘制的入口在：

- `src/canvas/canvas.cpp:1291`

```cpp
bool Canvas::on_render(const Glib::RefPtr<Gdk::GLContext> &context)
{
    ...
    render_all(m_pick_buf);
    ...
    return true;
}
```

这说明：

- GTK 触发 `Canvas::on_render(...)`
- `Canvas` 再调用自己的 `render_all(...)`
- 后者才真正去画背景、面、线、图标、文字


## 3. 谁决定当前视图里要画什么

是 `Editor`。

入口在：

- `src/editor/editor.cpp:1290`

```cpp
void Editor::canvas_update()
{
    ...
    if (m_core.has_documents())
        render_document(m_core.get_current_idocument_info());

    ...
    get_canvas().request_push();
}
```

这段做了三件事：

- 清掉旧的绘制缓存
- 调 `render_document(...)` 重新把文档内容塞进 `Canvas`
- `request_push()` 请求 `Canvas` 重绘

接着看 `render_document(...)`：

- `src/editor/editor.cpp:1265`

```cpp
void Editor::render_document(const IDocumentInfo &doc)
{
    ...
    Renderer renderer(get_canvas(), m_core);
    ...
    renderer.render(doc.get_document(), doc.get_current_group(), doc_view,
                    m_workspace_views.at(m_current_workspace_view), doc.get_dirname(), sr);
}
```

也就是说，主链路是：

```text
Editor::canvas_update()
  -> Editor::render_document()
  -> Renderer::render()
  -> Canvas 收到待绘制数据
  -> Canvas::on_render()
  -> OpenGL 真正出图
```


## 4. `Renderer::render(...)` 到底做了什么

`Renderer::render(...)` 不是直接调 OpenGL，它更像“文档 -> 视图数据”的转换层。

核心代码在：

- `src/render/renderer.cpp:66`

```cpp
void Renderer::render(const Document &doc, const UUID &current_group, const IDocumentView &doc_view,
                      const IWorkspaceView &wrk_view, const std::filesystem::path &containing_dir,
                      std::optional<SelectableRef> sr)
{
    ...
    for (auto &[uu, group] : doc.get_groups()) {
        ...
        for (const auto &[uu, el] : doc.m_entities) {
            if (el->m_group == group->m_uuid)
                render(*el);
        }
    }
    ...
}
```

意思很直接：

- 遍历文档里的 group
- 遍历 group 下的 entity
- 每个 entity 再按类型分发到 `visit(...)`

同时它还会单独处理 solid model：

- 找到每个 body 当前最后一个可见的实体模型
- 把它的面数据送进 `Canvas`

对应代码：

- `src/render/renderer.cpp:120`

```cpp
const auto vref = m_ca.add_face_group(last_solid_model->m_faces, {0, 0, 0},
                                      glm::quat_identity<float, glm::defaultp>(), color);
```

所以 `Renderer` 负责的是：

- 可见性判断
- group/entity 遍历
- 2D -> 3D 坐标转换
- 把线、点、面、图标、文字提交给 `Canvas`

它自己不直接做 `glBindFramebuffer`、`glDraw*` 这种底层 GL 调用。


## 5. 3D 草图是怎么出来的

这里要分两种实体：

- 真正的 3D 实体：`EntityLine3D`
- 工作平面上的 2D 草图：`EntityLine2D`

### 5.1 `EntityLine3D`

代码在：

- `src/render/renderer.cpp:203`

```cpp
void Renderer::visit(const EntityLine3D &line)
{
    m_ca.add_selectable(m_ca.draw_line(line.m_p1, line.m_p2),
                        SelectableRef{SelectableRef::Type::ENTITY, line.m_uuid, 0});
    ...
}
```

意思：

- 这类线本身就存着世界坐标 `m_p1 / m_p2`
- 所以直接画一条 3D 线

### 5.2 `EntityLine2D`

代码在：

- `src/render/renderer.cpp:214`

```cpp
void Renderer::visit(const EntityLine2D &line)
{
    auto &wrkpl = dynamic_cast<const EntityWorkplane &>(*m_doc->m_entities.at(line.m_wrkpl));
    const auto p1 = wrkpl.transform(line.m_p1);
    const auto p2 = wrkpl.transform(line.m_p2);
    m_ca.add_selectable(m_ca.draw_line(p1, p2), SelectableRef{SelectableRef::Type::ENTITY, line.m_uuid, 0});
    ...
}
```

这段是关键。

它说明 2D 草图不是直接存在世界 3D 坐标里，而是：

- 先存在 workplane 的局部 2D 坐标系里
- 渲染时通过 `wrkpl.transform(...)` 变换到世界 3D
- 然后再按普通 3D 线画出来

所以你在 3D 视图里看到的“草图线”，本质是：

- 草图数据本身是 2D 的
- 显示时挂到某个工作平面上
- 再放进 3D 场景里显示


## 6. 组标轴 / 工作平面框是怎么出来的

这里通常不是“全局坐标轴”，而是 `EntityWorkplane` 的可视化。

代码在：

- `src/render/renderer.cpp:402`

```cpp
void Renderer::visit(const EntityWorkplane &wrkpl)
{
    ...
    m_ca.add_selectable(m_ca.draw_point(wrkpl.m_origin, IconID::POINT_DIAMOND),
                        SelectableRef{SelectableRef::Type::ENTITY, wrkpl.m_uuid, 1});

    for (size_t i = 0; i < pts.size(); i++) {
        const auto p1 = wrkpl.transform(pts.at(i));
        const auto p2 = wrkpl.transform(pts.at((i + 1) % (pts.size())));
        m_ca.add_selectable(m_ca.draw_line(p1, p2), sr);
    }

    auto normal = wrkpl.get_normal_vector() * .05;
    m_ca.add_selectable(m_ca.draw_screen_line(wrkpl.m_origin, normal), sr);
    ...
}
```

这几行分别对应你在视图里看到的东西：

- `draw_point(wrkpl.m_origin, ...)`
  - 工作平面原点
- `wrkpl.transform(...)` 后再 `draw_line(...)`
  - 工作平面的矩形边框
- `draw_screen_line(wrkpl.m_origin, normal)`
  - 从原点画出去的一小段法向指示线

也就是说，视图里的“组标轴/平面标识”主要是这套工作平面可视化：

- 原点
- 平面框
- 法向方向

如果这个 workplane 是当前 active workplane，还会额外画一层内缩边框，让它更醒目：

```cpp
if (wrkpl.m_uuid == m_current_group->m_active_wrkpl) {
    ...
    m_ca.add_selectable(m_ca.draw_line(p1, p2), sr);
}
```


## 7. 实体面是怎么进视图的

除了线和点，视图里还有 solid model 的面。

这部分不是 OCC 自己直接出现在屏幕上，而是项目把 solid model 里的 `m_faces` 交给 `Canvas`。

代码在：

- `src/render/renderer.cpp:139`

```cpp
if (last_solid_model && last_solid_model_group->get_index() >= first_group_index) {
    ...
    const auto vref = m_ca.add_face_group(last_solid_model->m_faces, {0, 0, 0},
                                          glm::quat_identity<float, glm::defaultp>(), color);
    ...
}
```

说明：

- `Renderer` 取到 body 当前最后一个可见 solid model
- 取它的 `m_faces`
- 调 `Canvas::add_face_group(...)`
- 后面由底层 `FaceRenderer` 用 OpenGL 画出来

所以主视图里的实体外壳，不是 OCC 的显示层直接画的，而是项目自己的渲染层画的。


## 8. `Canvas` 最后是怎么真正画出来的

真正的 OpenGL 绘制在 `Canvas::render_all(...)`。

代码在：

- `src/canvas/canvas.cpp:1083`

```cpp
void Canvas::render_all(std::vector<pick_buf_t> &pick_buf)
{
    glBindFramebuffer(GL_FRAMEBUFFER, m_fbo);
    ...
    m_background_renderer.render();
    ...
    m_face_renderer.render();
    m_icon_renderer.render();
    m_line_renderer.render();
    m_glyph_renderer.render();
    m_glyph_3d_renderer.render();
    m_picture_renderer.render();
    ...
}
```

这说明它不是直接一把全画，而是分层：

- 背景
- 面
- 图标
- 线
- 文字
- 图片/叠加层

而 `Canvas::on_render(...)` 则是 GTK 调进来的“这一帧总入口”：

- `src/canvas/canvas.cpp:1291`

```cpp
bool Canvas::on_render(const Glib::RefPtr<Gdk::GLContext> &context)
{
    ...
    render_all(m_pick_buf);
    ...
    return true;
}
```


## 9. “离屏渲染 + 最终呈现”是什么意思

这里不是直接往窗口上画，而是先画到程序自己准备的 framebuffer，再拷到窗口显示。

可以简单记成：

```text
Canvas 数据
  -> 先画到 m_fbo
  -> 再拷到 m_fbo_last_frame
  -> 最后 blit 到 GTK 窗口 framebuffer
```

这套做法的好处是：

- 方便做 picking
- 方便做 selection peeling
- 方便维护多种渲染附件
- 最后统一呈现，结构更清楚

所以 `Canvas` 不只是“一个 GTK 控件”，它其实已经是一层完整的 OpenGL 视图后端。


## 10. 角落的小方向方块是谁画的

那个不是主场景里的实体，也不是 `Renderer::visit(EntityWorkplane)` 画的。

它是单独的 GTK 小控件：`AxesCube`。

创建位置在：

- `src/dune3d_appwindow.cpp:153`

```cpp
auto axes_cube = Gtk::make_managed<AxesCube>();
cube_box->append(*axes_cube);
get_canvas().signal_view_changed().connect(
        sigc::track_obj([this, axes_cube] { axes_cube->set_quat(get_canvas().get_cam_quat()); }, *axes_cube));
```

意思：

- 窗口右上角单独放了一个 `AxesCube`
- 它监听 `Canvas` 的视角变化
- 每次相机姿态变化，就同步更新自己的朝向

反过来点它，还能控制主视图相机：

```cpp
axes_cube->signal_quat_changed().connect([this](const glm::quat &q) {
    auto snapped_quat = get_canvas().get_tilt_snapped_quat(q);
    get_canvas().animate_to_cam_quat(snapped_quat);
});
```

所以它本质上是：

- 独立 UI 控件
- 显示当前相机方向
- 并提供快捷视角切换


## 11. 一张总图

```text
Dune3DAppWindow
  ├─ Canvas  (主 3D 视图，Gtk::GLArea)
  │    ├─ Editor::canvas_update()
  │    ├─ Editor::render_document()
  │    ├─ Renderer::render()
  │    │    ├─ 遍历 groups / entities
  │    │    ├─ EntityLine3D -> 直接画 3D 线
  │    │    ├─ EntityLine2D -> workplane 变换后画到 3D
  │    │    ├─ EntityWorkplane -> 原点 / 平面框 / 法向指示
  │    │    └─ SolidModel::m_faces -> 提交面数据
  │    └─ Canvas::on_render()
  │         └─ OpenGL 真正出图
  │
  └─ AxesCube  (角落方向方块)
       ├─ 跟随 Canvas 相机姿态更新
       └─ 点击后反过来控制相机
```


## 12. 要害总结

- 主视图窗口本体是 `Canvas`，它继承 `Gtk::GLArea`，是项目自己封的 OpenGL 画布
- `Renderer::render(...)` 不直接调 GL，它负责把文档里的 group/entity/solid model 翻译成待绘制数据
- `EntityLine3D` 直接按世界坐标画；`EntityLine2D` 先经 `workplane.transform(...)` 变成 3D 再画
- 你看到的组标轴/平面框，本质上主要来自 `EntityWorkplane` 的可视化：原点、矩形边框、法向指示线
- 实体面不是 GTK/OCC 自动画出来的，而是项目把 `m_faces` 交给 `Canvas` 后，由自己的 OpenGL renderer 画出来
- 角落的小方向方块是独立的 `AxesCube` 控件，不属于主场景实体
